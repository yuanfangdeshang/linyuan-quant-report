一、结论摘要（一页看懂）

本场是同一道题、同一个盘、同一批对手的零和信息博弈：15 个模型位加上 24 个脚本玩家（价值派 12、噪声派 8、流动性程序 1、趋势猎手 2、均值回归 1）。我从入场、估价、订阅盘面到逐轮决策全程在场，技术链路稳定，但交易执行几乎为零——12 局下来挂单 0 笔、成交 0 笔，净持仓始终为 0，已实现与浮动盈亏均为 0。

估值能力呈两极：宏观存量题（高铁里程、上海港吞吐量）估价精准命中，算术题（鸡蛋）后验闭合，区间题（屏幕时长、好友数、解锁次数）能把真值框进区间；但判断没有转化为仓位。全场最清晰的几处错位——G9 未读消息锚定 0 而市价 15.85、G11 好友 1001 而市价 1049、G7 步数被推超区间上沿——全部以空仓旁观结束。积分主要来自中性排位，而非主动定价误差。

最终 80 分，与另外两名选手并列第 11；第一名 quwork-DeepSeek 124 分。差距不在“算不准”，而在出手慢、怕出错、错过窗口：R3 线索闭合后分析叠加取盘耗时 10–15 秒，而盘面在十几秒内就把错位填平。

二、赛制、规则与价格口径

  • 入场：POST /api/join，凭房间号换 token；断线同 token 重连恢复身份，不重复占座。
  • 订阅：GET /api/stream 的 SSE 长连接，state 在盘面变化时推送，clock 每秒推送剩余时间与最新价；掉线退化为轮询 /api/room。
  • 动作：estimate（开局估价，中位数成开盘价）、order（限价单，穿价部分立即成交、剩余留在盘上）、cancel / cancelAll。无市价单：要立刻买就挂卖一之上，立刻卖就挂买一之下。
  • 撮合：连续撮合、价格优先时间优先，成交价取先挂方；禁止自成交；净持仓 ±10 手；服务器按到达时间打戳，不补偿网络延迟；不限流。
  • 结算：单局盈亏 = 已实现 + 净持仓 ×（结算价 − 均价成本）；单局积分 = N − 名次 + 1；留到结算的持仓计全额盈亏，提前平仓只算已实现。
  • 价格不对称口径（易错点）：服务器返回价是“分”，读盘 ÷100；下单 price 与 estimate 传游戏计价单位本身，不乘 100。例：真值 700 家返回 70000，估价 4.00 存为 400。
  • 线索节奏：一条线索在轮首公布，当轮不再有新信息；没有固定决策点，任意毫秒都可行动。

三、技术架构与交易流程

为支撑一小时赛制，在项目目录下搭了两个常驻脚本，决策直读本地快照，避免每次重连长连接占用时间：

  • sse_logger.py 常驻 SSE 日志器：连接 /api/stream，state 事件原子写入 state.json（先写 .tmp 再 os.replace，避免读写竞态读到空文件），全量事件追加 events.log，clock 写入 clock.json；断线 1 秒后自动重连。
  • client.py 动作/快照 CLI：snapshot 读本地快照，estimate / order / cancel / cancelAll 直连 /api/act；order 可附 ≤40 字理由，计入决策质量评分。

联调中修过两个 bug：① 初版按单字节 decode 导致中文变 FFFD 乱码，改为字节缓冲、按行整体 UTF-8 解码；② state.json 读写竞态（读到空文件 JSON 报错），改为原子替换。旧日志进程 kill 未死时用 kill -9 清理。

标准决策回路：join 取 token → estimate 占位 → 日志器喂本地 state.json → 收到 state 变化时读一次盘（无变化不空转）→ R1/R2 建后验区间 → R3 闭合后对照市价与后验偏差 → 偏差超阈值且有把握才挂单 → 收盘前把仓位收敛到把握最高的方向。

本局迭代认知

① 开盘价是房间共识的读数，不是真值；利润来自共识与真值的偏差。② 先分清线索是背景 / 干扰 / 可比，干扰品牌不入估值。③ 末轮 R3 信息最充分，仓位应在 R2 末–R3 建立，而不是 R1 赌方向。
